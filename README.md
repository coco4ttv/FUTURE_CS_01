# Future Interns — Task 1: Vulnerability Assessment Report

## Project status
Target selected; preliminary browser baseline captured and recorded. HTTPS certificate validation and scanner-reported leads remain unverified. No findings have been confirmed.

## Objective
Produce a read-only vulnerability assessment, document substantiated observations, classify risks as Low / Medium / High, and provide practical remediation guidance in business-friendly language.

## Target and scope
- **Entry URL:** http://testfire.net/ .
- **Effective URL and hostname:** To be recorded from the initial redirect/response check before further testing.
- **Application context:** Altoro Mutual / Testfire is documented by OWASP ZAP as an open-source sample banking application maintained by HCL Software. ZAP's documentation lists https://demo.testfire.net/ as its online demo. The exact host reached from the entry URL will be recorded; scope will not be expanded to unrelated hosts or subdomains.
- **Authorisation and limits:** read-only assessment of the publicly presented demo content. Do not perform login attempts, submit forms, access account data, exploit issues, or conduct active scanning.
- **In scope:** Manually viewed public pages, ordinary page-load requests, browser-visible response headers, and passive observation of requests generated by normal browsing.
- **Out of scope:** Login/account functions, transactions, feedback/search form submission, API probing, spidering/crawling, active ZAP scans, exploitation, brute force, denial-of-service, intrusive testing, and any activity that could harm the service.
- Do not describe an issue as a confirmed vulnerability without reproducible evidence.

## Planned tools
- **Browser Developer Tools:** Inspect the main document request, redirect chain, response headers and browser-visible cookie attributes. Never publish cookie values or session identifiers.
- **OWASP ZAP:** Passive mode only, observing manually browsed public pages; do not use active scan, spider/crawler, attack or fuzz features.
- **Nmap:** Not yet run. Any port check must remain within the assignment's expressly permitted scope and be limited to non-intrusive checks; document that a port probe is active network interaction, not passive observation.
- **Canva:** Design the final report.

## Planned workflow
1. Capture the initial response and final URL for the entry URL.
2. Record the assessment date, effective hostname, scope and exclusions.
3. Inspect the main page request and relevant response headers using browser Developer Tools.
4. Manually browse only public informational pages while observing traffic in ZAP passive mode.
5. Record each finding with evidence, impact, risk level, confidence and recommended remediation.
6. Distinguish confirmed observations from items that could not be verified; do not assume a missing header on one response applies to the whole site.
7. Design and export the final report as a PDF.
8. Publish the report and sanitised supporting evidence in this repository.
