# Future Interns — Task 1: Vulnerability Assessment Report

## Project status
Target selected; preliminary browser baseline captured and recorded. HTTPS certificate validation remains unverified. No findings have been confirmed.

## Objective
Produce a read-only vulnerability assessment, document substantiated observations, classify risks as Low / Medium / High, and provide practical remediation guidance in business-friendly language.

## Target and scope
- **Entry URL:** http://testfire.net/
- **Effective URL and hostname:** To be recorded from the initial response and redirect checks.
- **Application context:** Altoro Mutual / Testfire is a demonstration banking application. Assessment is limited to the publicly presented demo content.
- **Authorisation and limits:** Read-only assessment of public pages only. Do not perform login attempts, submit forms, access account data, exploit issues, or conduct active scanning.
- **In scope:** Manually viewed public pages, ordinary page-load requests, browser-visible response headers, cookie security attributes (without exposing cookie values), TLS certificate inspection, and passive observation of traffic generated by normal browsing.
- **Out of scope:** Nmap and all port/service scanning (not authorised for this assessment); login/account functions; transactions; feedback/search form submission; API probing; spidering/crawling; active ZAP scans; exploitation; brute force; denial-of-service; intrusive testing; and any activity that could harm the service.
- Do not describe an issue as a confirmed vulnerability without reproducible evidence.

## Tools
- **Chrome Developer Tools:** Inspect ordinary browser requests, response headers, redirect behaviour and cookie security attributes. Never publish cookie values or session identifiers.
- **OpenSSL:** Inspect the TLS certificate presented for the target and attempt certificate/hostname verification. This is a connection to the target's TLS service, limited to certificate inspection.
- **OWASP ZAP:** Passive mode only, observing manually browsed public pages; do not use active scan, spider/crawler, attack or fuzz features.
- **Canva:** Design the final report.
- **Nmap:** Not used. Port and service scanning is not authorised for this assessment.

## Planned workflow
1. Record the initial response and final URL for the entry URL.
2. Record the assessment date, effective hostname, scope and exclusions.
3. Inspect the main page request and relevant response headers using browser Developer Tools.
4. Inspect the presented TLS certificate and record verification results without bypassing browser warnings.
5. Manually browse only public informational pages while observing traffic in ZAP passive mode.
6. Record each finding with evidence, impact, risk level, confidence and recommended remediation.
7. Distinguish confirmed observations from items that could not be verified; do not assume a missing header on one response applies to the entire site.
8. Design and export the final report as a PDF.
9. Publish the report and sanitised supporting evidence in this repository.
